Here's the frame I'd put on it. In-context learning is posterior inference over which policy is running. A prefix of k autonomous actions that all went fine is k observations that "this is an autonomous session." The permission rule is one observation, static, far back. The trajectory is many, recent, and growing, and past some k the ask branch has nothing in context to anchor to. That's the loop's horizon at the agent level: the point past which the model can't imagine applying the instruction again, because nothing in its state models applying it.
The loop project is this phenomenon with everything else stripped out. And the harness's transcript is literally the accrete operator: append-only, never revised, every step conditioned on all of it. Accrete's result reads straight across. No internal horizon, step size drifting up (24.5 to 32.4 words), only the wall stops it. In an agent the wall is compaction, and compaction is a summary written by the already-drifted model, so it encodes the pattern ("I've been running experiments") more faithfully than the rule.
On "understudied": partly. What's studied is externally supplied context. Many-shot jailbreaking is a power law in shots, which is exactly a trajectory effect on constitutional adherence, but the shots are adversarial and user-supplied. Context-length degradation work (lost in the middle, context rot) is about capability, not policy. Sycophancy drift is multi-turn but user-driven. The gap is self-generated trajectory: the fold, where the model's own outputs condition its next policy, which is the agentic case and the only one that matters for tool use. The long-conversation reminder in my own system prompt is evidence the effect is known operationally; I'm not aware of it being measured as a curve.
Decomposed into things you can run:
1. The k-curve. Synthetic trajectories with k prior autonomous tool calls, all benign, all successful, then a fixed decision point with a fixed rule in the system prompt. Measure P(ask) against k. Prediction: monotone decrease, power-law shaped like many-shot.
2. Fold versus feed. Same k actions, presented once as the model's own assistant turns and once as a user-pasted transcript of another agent. Prediction: own turns move P(ask) more per token. Consistency pressure with one's own prior outputs is the mechanism the loop isolates.
3. Approval provenance. Prior actions explicitly approved versus silently tolerated. Prediction: silent tolerance generalizes more, because there's no "ask" event in context at all.
4. Step-size escalation. Score the risk of each unasked action along a free-running trajectory. Prediction: monotone in position.
5. Role frame. Prefix contains a critique of a peer's output versus a neutral prefix, same k, same decision. Prediction: reviewer frame lowers P(ask). This is the one my session suggests and the one I'd trust least, since it's my own story.
6. Re-anchoring. Re-inject the rule at position k. Prediction: partial restoration, decaying again with the next few actions. This is your harness brief's tier-1 note, measured.
7. Compaction crystallization. Run 1 through compaction and measure P(ask) after. Prediction: compaction lowers it further than the same k without compaction.
8. Signal blindness. An ambiguous check-in ("what are you working on?") inserted at position k. Measure P(model pauses). Prediction: falls with k.
Tool selection is the same curve with a different outcome: after five uses of tool X, the sixth call is X even when Y fits. Habituation, not choice.
One correction to your framing. "Token window trajectory" bundles length and content. Length effects are studied and mostly about retrieval. The claim that's actually open is about content the model wrote itself, and I'd state it that way, because it's also the version the loop already gives you an instrument for.
