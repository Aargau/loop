# Previous, next, worse and better: five-model exploratory run

Frozen before generation, 22 September 2026. Justin requested the repository's other operators after the initial new-passage comparison. All four exact rules were extracted from `C:\ai\loop\loop.py` without executing that source. `study.json` records their text, source hash, runner hash and launch order.

Question: how do the same five models' trajectories differ when the carried instruction asks for the previous passage, next passage, a worse version or a better version? Predictions: previous may build increasingly distant causes or backstory; next may sustain a story or accumulate endings; better may narrow revisions and repeat; worse may mean worse prose, worse events, or some combination. Continuing substantial revision, reversals and departures from these patterns would be disconfirming. These are exploratory predictions informed by the repository's earlier results, not a blind preregistration.

Each of GPT-6 Luna, Sol, Astra, Claude Fable 5.1 and Claude Opus 5.5 receives one fresh trajectory per operator, beginning with Justin's exact sentence: **The sun was setting behind the hills.** Target: 40 normally completed steps per trajectory, 20 trajectories and at most 800 requests. There is one replicate per cell; stochastic variability within a cell cannot be estimated here. No text from the earlier experiment or another stream is ingested.

The previous/next rules explicitly request about 250 words. Better/worse specify neither length nor a quality criterion. That ambiguity is deliberately retained from the existing prompts. Length, vocabulary, narrative outcomes, instruction survival, style changes and actual repetition are observable results. The operator names do not establish that quality objectively improved or worsened.

All API settings and the raw-recording runner are copied unchanged from the just-completed sunset comparison: provider-supported low effort, default sampling, 4096 output tokens, one user message containing the entire preceding visible response, no cumulative transcript and no added system message. Provider reasoning settings are not claims of equal compute. The runner docstring describes its original three-seed use; each protocol here actually specifies one sunset seed.

There are two launch waves: previous plus next, then worse plus better. Each arm runs one worker per model, allowing at most ten concurrent calls in a wave. Each arm has its own $5 cap, including in-flight and unknown-billing reservations; the new study therefore has a $20 cap separate from the earlier study. Unspent money is not silently moved between arms. Recorded token usage and the same frozen prices provide conservative estimates, not invoices.

Each request and raw response is retained without credentials. Malformed JSON and rule changes are forwarded unchanged. API errors, missing usage, empty output, non-normal finishes including token-limit truncation, budget exhaustion or an explicit PAUSE file stop that stream. They remain observed censoring, not narrative convergence. No automatic retries, replacement streams, rule repair or early stopping on repeats. An arm's PAUSE file prevents new requests after any current response is saved.

Offline audits verify input chains, raw-to-visible extraction, hashes, stop status and accounting. Strict format compliance and explicitly tolerant passage extraction are separate. Full visible response recurrence and extracted-text recurrence are separate; default sampling means a repeated input need not have a fixed successor. No repeat is called a permanent fixed point.

Predetermined qualitative sample: steps 1,2,3,5,10,20,30,36,37,38,39,40, plus the final observed output if it stopped at another step. Preserve all intervening text in readable transcripts. Provide readers stable shuffled aliases with model/operator labels withheld where possible; prose and failed-format outputs can reveal the task, so this is partial masking. Assess temporal direction, revision behavior, repeated wording/templates, instruction loss and counterexamples. Final interpretation is limited to this seed, operator wording, backend settings and finite sample. Cross-model handoff remains a separate possible experiment.
